== Что реализовано

[cols="1,3", options="header"]
|===
| Компонент | Статус

| Главная страница `/`
| Реализована: hero, описание механики, формы регистрации работодателя и кандидата

| Страница подборки `/list/[listId]`
| Реализована: анонимные карточки кандидатов (без имени и контактов), теги, summary, disclaimer о конфиденциальности. Кнопка «Хочу связаться» — функциональна: записывает запрос в лист «Contact Requests». Блок «Не нашли подходящих кандидатов?» — виден только при наличии токена работодателя (`?e=`). Noindex. Доступ только по `?e=[employer_token]` (персонализированная подборка) или `?secret=[EDITOR_SECRET]` (редактор); без параметров — 404.

| Страница профиля `/profile/[id]`
| Реализована: полный профиль кандидата. Недоступна с публичных страниц. Noindex.

| Редактор `/editor`
| Реализован: боковое меню с разделами (Выпуски / Работодатели / Кандидаты / Запросы / Настройки). Выпуски: история кампаний, проверка пустой книги, ссылка на подборку с секретом. Работодатели: три коллапсируемые группы (На проверке / Отклонён / Подтверждён). Кандидаты: три коллапсируемые группы (На проверке / Активные / Отклонённые), кнопки «Добавить» / «Отклонить». Запросы: управление запросами на контакт с двумя разделами («Общие запросы» и «По кандидатам»), цветные бейджи статусов, смена статуса через выпадающий список. Настройки: идемпотентная миграция всех колонок Google Sheets (профили, работодатели, кандидаты) одной кнопкой.

| SendPulse интеграция
| Реализована: адресные книги (авто-создание), email-кампании, пагинация, TTL кэша книг (60 с). Проверка пустой книги до запуска рассылки.

| API `/api/publish/[listId]`
| Реализован: curl-triggered публикация с авторизацией по токену

| Регистрация работодателя
| Реализована: форма → Google Sheets со статусом «На проверке». В SendPulse не добавляется — только после подтверждения редактором.

| Подтверждение работодателя
| Реализовано: в `/editor` редактор подтверждает или отклоняет заявку. При подтверждении — добавление в SendPulse (мастер-книга + книги выбранных стримов).

| Регистрация кандидата
| Реализована: форма → Google Sheets (SendPulse не используется — кандидаты не являются подписчиками рассылки)

| Google Sheets интеграция
| Реализована: чтение профилей, подборок, стримов, работодателей; запись регистраций; миграция колонок (`ensureProfileColumns`)

| Robots / noindex
| Реализовано: `app/robots.ts` (Disallow: /list/, /profile/), meta robots noindex на страницах подборки и профиля

| Персонализация рассылок
| Реализована: токен работодателя (`crypto.randomUUID()`, колонка `ID` в Employers); `employer_token` передаётся в SendPulse; ссылка в письме `/list/[listId]?e={{employer_token}}`; `getEmployerByToken()` и `filterCandidatesForEmployer()` в `lib/sheets.ts`; поля `excludedCompanies`/`excludedIndustries` в `Profile`.

| Запросы на контакт (Contact Requests)
| Хранятся в PostgreSQL (Neon) через Drizzle ORM — таблица `contactRequests`. Два типа: по кандидату (`candidateId` заполнен, 7 статусов) и общий (`candidateId` пуст, 3 статуса). Функции в `lib/db/contact-requests.ts`. Исторические данные в Google Sheets остаются как архив.

| Neon + Drizzle ORM
| ✅ TASK-DB-1 + TASK-DB-2. PostgreSQL через Vercel Marketplace (Neon). Схема — `lib/db/schema.ts`, клиент — `lib/db/index.ts` (neon-http driver). Миграция — `scripts/migrate.mjs`. Обход TLS корпоративного прокси в локальной среде: `NODE_TLS_REJECT_UNAUTHORIZED=0` при `NODE_ENV !== "production"` в `lib/db/index.ts`.

| Стримы — раздел редактора
| Страница `/editor/streams` — отображение стримов из Google Sheets (Stream / Тип / Описание). Только чтение. Пункт «Стримы» добавлен в `EditorNav` (иконка Layers, между «Запросы» и «Настройки»).

== Задачи на доработку

=== 🟠 Важно — бизнес-правила

==== TASK-05: Правила публикации кандидатов

*Что сейчас:* нет отслеживания дат публикации, нет защиты от нарушения правил.

*По ТЗ (§13):*

* Первая публикация → фиксируется дата.
* Через 2 недели возможна повторная публикация.

=== Анализ

Google Sheets достаточен для MVP, но создаёт структурные ограничения по мере роста:

* *Производительность:* каждый запрос — HTTP-вызов к Sheets API; нет индексов, фильтрация только in-memory. При 500+ кандидатах и 100+ работодателях это станет ощутимым.
* *Целостность данных:* нет foreign keys и транзакций — связи между листами поддерживаются вручную (candidateId, employerToken — строки без ограничений).
* *Сложные запросы:* фильтрация, JOIN-подобные операции (подборка → кандидаты → работодатели) делаются in-memory в `lib/sheets.ts`, что увеличивает объём данных, которые нужно держать в памяти.
* *Параллельные записи:* append-only подход с `rowIndex` — хрупкий при одновременных операциях.
* *Лимиты API:* Google Sheets API — 300 запросов в минуту на проект.

==== Vercel Global Config (бывший Edge Config) — не БД

Отдельный продукт Vercel: глобально реплицированное key-value хранилище, читается прямо на CDN-ноде в регионе пользователя — без обращения к серверу. Чтение < 1 мс, P99 ≈ 15 мс.

*Лимиты:* 1 МБ на стор, 100 000 чтений/мес (бесплатно), 100 записей/мес (бесплатно), распространение записи — до 10 секунд по всем регионам.

*Когда подходит:* данные читаются постоянно, записываются редко — feature flags, списки стран/тегов, конфигурация. Не подходит для транзакционных данных, фильтрации, запросов — это не база данных.

*Применимость для TalentStreams:* список стримов (`getStreams()`) — идеальный кандидат. Стримов меньше 20, они меняются крайне редко, но запрашиваются при каждой загрузке регистрационной формы. Вместо чтения из БД можно хранить в Global Config и читать за < 1 мс. Остальные данные (кандидаты, работодатели, запросы) — слишком динамичны и не вписываются в 1 МБ.

== Перенос стримов в Vercel Global Config

Стримы — идеальный кандидат для Global Config: их меньше 20, меняются редко (раз в несколько месяцев), но читаются при каждой загрузке регистрационной формы. Чтение из Global Config происходит на CDN-ноде за < 1 мс без обращения к серверу.

*Ограничение:* Global Config доступен только для чтения из app-кода. Запись — только через Vercel Management API с `VERCEL_API_TOKEN`. Это нормально: изменения стримов редкие, а UI в редакторе будет вызывать этот API через Server Action.

*Независимость:* задачи не зависят от TASK-DB — Global Config и Neon это разные продукты.

=== TASK-GC-1: Инфраструктура и первичное наполнение

. Создать Edge Config store в Vercel Dashboard (Storage → Edge Config).
. Установить `@vercel/edge-config`.
. Добавить переменные окружения:
  * `EDGE_CONFIG` — connection string (проставляется автоматически при подключении через Marketplace)
  * `VERCEL_API_TOKEN` — токен с правом на запись в Edge Config (создать в Vercel Account Settings → Tokens)
  * `EDGE_CONFIG_ID` — ID стора (вида `ecfg_...`, виден в дашборде)
. Записать начальные данные вручную через Vercel Dashboard или API: `{ "streams": ["Finance", "Tech", ...] }`.
. Убрать лист «Streams» из Google Sheets (или оставить как резервный).

*Сложность:* низкая.

---

=== TASK-GC-2: Замена getStreams()

Заменить реализацию `getStreams()` — сигнатура и все вызовы остаются прежними.

[source,ts]
----
// lib/streams.ts
import { get } from "@vercel/edge-config"

export async function getStreams(): Promise<string[]> {
  try {
    const streams = await get<string[]>("streams")
    return streams ?? []
  } catch {
    return []
  }
}
----

Обновить импорты в `app/page.tsx` и `app/actions.ts` (где используется `getStreams`): заменить `from "@/lib/sheets"` на `from "@/lib/streams"`.

*Сложность:* низкая.

=== TASK-GC-3: UI управления стримами в редакторе

NOTE: Страница `/editor/streams` уже существует (display-only, читает из Sheets — см. «Выполненные задачи → Стримы»). TASK-GC-3 добавляет к ней возможность изменения через Global Config.

Расширить существующую страницу `app/editor/streams/page.tsx`.

*Функциональность:*

* Список текущих стримов с кнопкой удаления у каждого.
* Форма добавления нового стрима (одно текстовое поле + кнопка).
* Переименование: клик по названию → inline-редактирование.

*Server Actions* (`app/actions.ts`):

[source,ts]
----
// Все три action-а читают текущий массив из Global Config,
// вносят изменение и пишут обновлённый массив обратно через Vercel API.

async function updateStreamsInConfig(streams: string[]): Promise<void> {
  await fetch(`https://api.vercel.com/v1/edge-config/${process.env.EDGE_CONFIG_ID}/items`, {
    method: "PATCH",
    headers: {
      Authorization: `Bearer ${process.env.VERCEL_API_TOKEN}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify({ items: [{ operation: "upsert", key: "streams", value: streams }] }),
  })
}

export async function addStream(name: string): Promise<void>     // append + updateStreamsInConfig
export async function deleteStream(name: string): Promise<void>  // filter out + updateStreamsInConfig
export async function renameStream(old: string, next: string): Promise<void> // map + updateStreamsInConfig
----

Все три action-а вызывают `revalidatePath("/editor/streams")` и `revalidatePath("/")` (форма регистрации на главной обновит список стримов).

Добавить пункт «Стримы» в `EditorNav` (между Настройками или как отдельный раздел).

*Сложность:* средняя — новая страница + три action-а + inline-редактирование.

NOTE: Задержка записи в Global Config — до 10 секунд до глобального распространения. Для управления стримами это несущественно.
