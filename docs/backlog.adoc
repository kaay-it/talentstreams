== Что реализовано

[cols="1,3", options="header"]
|===
| Компонент | Статус

| Главная страница `/`
| Реализована: hero, описание механики, формы регистрации работодателя и кандидата

| Страница подборки `/list/[listId]`
| Реализована: анонимные карточки кандидатов (без имени и контактов), теги, summary, disclaimer о конфиденциальности, кнопка «Хочу связаться» (заглушка). Noindex.

| Страница профиля `/profile/[id]`
| Реализована: полный профиль кандидата. Недоступна с публичных страниц. Noindex.

| Редактор `/editor`
| Реализован: список выпусков, статус отправки, история кампаний, проверка пустой адресной книги, секция подтверждения работодателей (три группы: На проверке / Отклонён / Подтверждён)

| SendPulse интеграция
| Реализована: адресные книги (авто-создание), email-кампании, пагинация, TTL кэша книг (60 с). Проверка пустой книги до запуска рассылки.

| API `/api/publish/[listId]`
| Реализован: curl-triggered публикация с авторизацией по токену

| Регистрация работодателя
| Реализована: форма → Google Sheets со статусом «На проверке». В SendPulse не добавляется — только после подтверждения редактором.

| Подтверждение работодателя
| Реализовано: в `/editor` редактор подтверждает или отклоняет заявку. При подтверждении — добавление в SendPulse (мастер-книга + книги выбранных стримов).

| Регистрация кандидата
| Реализована: форма → Google Sheets (SendPulse не используется — кандидаты не являются подписчиками рассылки)

| Google Sheets интеграция
| Реализована: чтение профилей, подборок, стримов, работодателей; запись регистраций; миграция колонок (`ensureProfileColumns`)

| Robots / noindex
| Реализовано: `app/robots.ts` (Disallow: /list/, /profile/), meta robots noindex на страницах подборки и профиля

===== Что нужно доделать

  `ID`, `Timestamp`, `List ID`, `Stream`, `Candidate ID`, `Employer Name`, `Company`, `Employer Email`, `Status`.
  `ID` — `crypto.randomUUID()`, генерируется при создании запроса.

===== Открытые вопросы — нужно решить перед реализацией

*Вопрос 1: Как идентифицировать работодателя?*

Страница подборки публичная, авторизации нет. Вариант «передать токен работодателя в ссылке» не подходит — SendPulse рассылает одно письмо с общим URL для всего адресбука, индивидуальные ссылки потребовали бы хранить токен каждого работодателя в SendPulse. Остаются два варианта:

* *Форма при нажатии* — кнопка открывает мини-форму с полями «Ваше имя», «Компания», «Email» перед отправкой. Данные работодателя точные, но есть лишний шаг.
* *Без идентификации* — сохранять только `candidateId + listId + timestamp`, поле Employer оставить пустым. Администратор сам выясняет кто прислал запрос (например, по ответному письму). Упрощает реализацию, но теряет контекст.

*Вопрос 2 — решено: уведомление администратора через SendPulse.*

Завести отдельную адресную книгу для администраторов (например, `Admins`). При поступлении запроса отправлять кампанию в эту книгу. Название книги задаётся через переменную окружения `SENDPULSE_ADMIN_BOOK_NAME`. Книга создаётся автоматически через существующий `getOrCreateBook`, как и остальные.

*Затрагивает:* `components/contact-button.tsx`, `app/actions.ts`, `lib/sheets.ts`.

==== TASK-05: Правила публикации кандидатов

*Что сейчас:* нет отслеживания дат публикации, нет защиты от нарушения правил.

*По ТЗ (§13):*

* Первая публикация → фиксируется дата.
* Через 2 недели возможна повторная публикация.
* После второй публикации — пауза 3 месяца.
* Кандидат может попросить статус «Не публиковать».

*Что нужно сделать:*

* Добавить в карточку кандидата (Google Sheets): дата первой публикации, дата последней публикации, статус (Активный / На паузе до даты / Не публиковать).
* В редакторе при выборе кандидатов для выпуска: показывать статус публикации и дату, с которой публикация снова разрешена.
* Предупреждение, если кандидат добавлен в подборку, но находится в паузе.
