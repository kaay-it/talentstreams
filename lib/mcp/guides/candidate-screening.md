# Скрининг кандидатов TalentStreams

Гайд описывает, как проверять кандидатов по критериям отсева и готовить рекомендацию. Решение принимает человек: ничего не меняй в базе без явного подтверждения.

## Порядок работы

1. Найди кандидатов: по ID/имени или `search_candidates(status: "На проверке", limit, offset)`. Ответ постраничный — листай `offset`, пока не пройдёшь нужный объём; при большом `total` уточни у пользователя объём пакета.
2. Для каждого: `get_candidate(id)` → `list_candidate_resumes` → `get_candidate_resume` (предпочитай файл ссылке, самую свежую версию).
3. Проверь каждый критерий из списка ниже. Для каждого определи результат:
   - **ОК** — критерий пройден;
   - **СТОП** — критерий не пройден, с доказательством (даты/должность из резюме или поле профиля);
   - **ФЛАГ** — критерий сработал, но он не отсекает, а отправляет на ручную проверку;
   - **?** — данных недостаточно (например, нет дат).
4. Вердикт:
   - хотя бы один **СТОП** → «рекомендую отклонить»;
   - нет СТОП, но есть **ФЛАГ** или **?** → «нужна ручная проверка» (с перечнем флагов);
   - все ОК → «проходит скрининг».
5. Покажи результат на ревью (формат ниже). **Никогда не вызывай `reject_candidate`, `approve_candidate`, `pause_candidate` или `update_candidate` автоматически.** Меняй статус только после явного подтверждения пользователя по конкретным кандидатам («отклоняй 1, 3, 5», «ок, отклоняй всех рекомендованных»).
6. При пакетной работе в конце — сводка: сколько проверено, сколько к отклонению, на ручную проверку, проходят.

## Критерии отсева

Список будет пополняться: новые критерии добавляются в конец с очередным номером и пометкой СТОП или ФЛАГ.

**К1. Стаж на последнем месте работы — меньше 1 года → СТОП.**
Считай от даты начала до даты окончания; для текущего места («н.в.», «по настоящее время») — до сегодняшней даты. Смена должности внутри одной компании — одно место. Нет дат — **?**.

**К2. Короткий стаж на последних местах работы → СТОП.**
Возьми три последних места работы (включая текущее) и посчитай суммарный стаж для каждой пары (1+2, 1+3, 2+3). Если хотя бы одна пара даёт 3 года и больше — **ОК**; если все пары меньше 3 лет — **СТОП**. Если мест меньше трёх — сложи все имеющиеся и сравни с 3 годами.

**К3. Возраст старше 55 лет → ФЛАГ.**
**К4. Возраст младше 23 лет → ФЛАГ.**
Если возраст или дата рождения указаны явно — используй их. Если нет — оцени: год окончания вуза и ~22 года на момент выпуска, либо начало карьеры и ~21 год. Оценённый возраст помечай «≈ N (оценка по …)». Если оценить не из чего — **?**.
К3 и К4 никогда не дают СТОП — только ФЛАГ и ручную проверку, даже если возраст указан явно.

**К5. В опыте нет ни одного из ключевых слов → СТОП.**
Ключевые слова:

- русские: руководитель, управляющий, директор, начальник, тимлид, лидер (кластера/трайба/направления), партнёр, соучредитель, основатель;
- английские: senior, head, lead (team lead, tech lead, chapter lead), chief, director, manager, VP / vice president, partner, founder;
- C-level: CEO, COO, CTO, CIO, CFO, CMO, CPO, CCO, CDO, CHRO, CSO, CAIO и любая другая аббревиатура вида C?O.

Ищи в названиях должностей во всём опыте работы, без учёта регистра и с любыми словоформами (руководителя, управляющая, директором, Head of …). Достаточно одного совпадения в любой позиции.

**К6. Страна проживания в стоп-листе → ФЛАГ.**
Стоп-лист стран: Индия, Пакистан, Нигерия.
Источник: поле `countryPrimary`, если пусто — текущий город/страна из резюме. Не указана нигде — **?**. К6 никогда не даёт СТОП — только ручную проверку.

## Формат результата

Для одного кандидата:

```text
<Имя> — <вердикт>
К1 стаж на последнем месте: ОК / СТОП / ? — <место, даты, стаж>
К2 стаж на последних местах: ОК / СТОП / ? — <лучшая пара и её сумма>
К3–К4 возраст: ОК / ФЛАГ / ? — <значение: явное или «≈ N (оценка по …)»>
К5 ключевые слова: ОК / СТОП — <найденное слово и должность>
К6 страна: ОК / ФЛАГ / ? — <страна и источник>
```

Для пакета — сначала таблица (кандидат, вердикт, сработавшие критерии), затем детали только по «рекомендую отклонить» и «нужна ручная проверка».

## Правила

- Только факты из резюме и профиля. Единственное исключение — оценка возраста в К3–К4, и она всегда помечается как оценка.
- Нет данных — **?**, а не СТОП.
- Каждый СТОП и ФЛАГ подкрепляй конкретным доказательством (даты, должность, поле).
- Результаты скрининга (в том числе возраст и его оценку) не записывай в саммари и другие поля кандидата.
