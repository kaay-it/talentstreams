= TalentStreams
:toc: left
:toc-title: Содержание
:toclevels: 2

Платформа персонализированных подборок проверенных кандидатов для работодателей Центральной Азии.

Работодатели получают email-рассылку с анонимными карточками кандидатов (плюс, опционально, дублирующий пуш в Telegram и/или WhatsApp).
Ссылка в письме персонализирована — каждый работодатель видит только тех кандидатов, кто не исключил его компанию или отрасль из своих предпочтений.

== Технический стек

* *Next.js 16* (App Router, Server Components, Server Actions в `app/actions.ts`; `middleware.ts` — в 16.x переименованный `proxy.ts`)
* *TypeScript*
* *Neon (PostgreSQL)* — единственное хранилище «боевых» данных: кандидаты, работодатели, компании, стримы, выпуски/подборки, запросы на контакт, история резюме, настройки и вся служебная статистика (Drizzle ORM + neon-http driver)
* *Google Sheets* — НЕ часть боевого пути приложения; опциональный канал массового ввода кандидатов (менеджер заполняет таблицу вручную, кнопка на `/editor/settings` импортирует новые строки в Neon)
* *Vercel Blob* — приватное хранилище файлов резюме
* *SendPulse* — email-рассылки (адресные книги, кампании, merge-теги), транзакционные письма кандидатам и фоллоу-апы работодателям (SMTP API), Telegram-бот и WhatsApp-бот работодателей
* *Google AI Studio (Gemini)* — эмбеддинги для поиска дублей кандидатов
* *@modelcontextprotocol/sdk* — MCP-сервер (`/api/mcp`): поиск/правка кандидатов из Claude Desktop/claude.ai, с собственным OAuth 2.1-слоем (PKCE, Dynamic Client Registration)
* *Vercel Analytics*
* *Tailwind CSS + lucide-react*

== Переменные окружения

Создайте файл `.env.local` в корне проекта:

[source,env]
----
# Google Sheets — опциональный канал массового ввода (не боевой путь)
GOOGLE_SHEET_ID=...
GOOGLE_SERVICE_ACCOUNT_JSON={"type":"service_account","project_id":"...","private_key":"...","client_email":"..."}

# Neon (PostgreSQL)
DATABASE_URL=...

# Vercel Blob
BLOB_READ_WRITE_TOKEN=...

# SendPulse — email
SENDPULSE_CLIENT_ID=...
SENDPULSE_CLIENT_SECRET=...
SENDPULSE_MASTER_BOOK_NAME=Default
SENDPULSE_EMPLOYER_FROM_EMAIL=partner@example.com
SENDPULSE_EMPLOYER_FROM_NAME=TalentStreams Partner
SENDPULSE_CANDIDATE_FROM_EMAIL=career@example.com
SENDPULSE_CANDIDATE_FROM_NAME=TalentStreams Career
SENDPULSE_CANDIDATE_BOOK_NAME=Candidates
SENDPULSE_CANDIDATE_DIGEST_SEND_BOOK_NAME=Candidates Digest Manual

# SendPulse — Telegram-бот работодателей
SENDPULSE_TG_BOT_ID=...
SENDPULSE_TG_BOT_NAME=talentstreams_bot
SENDPULSE_TG_START_FLOW_ID=...

# SendPulse — WhatsApp-бот работодателей (пуш по одобренному Meta-шаблону)
SENDPULSE_WA_BOT_ID=...
SENDPULSE_WA_TEMPLATE_NAME=...

# Google AI Studio (Gemini) — поиск дублей кандидатов
GEMINI_API_KEY=...

# Приложение
APP_URL=https://your-domain.com
EDITOR_SECRET=your-secret-string
SESSION_SECRET=your-session-signing-secret
CRON_SECRET=your-cron-secret
----

`EDITOR_SECRET` защищает `/editor/*` (страницы, по `?secret=`) и `/api/publish` (заголовок `x-editor-token`) — без него страница возвращает 404, а API-роут отвечает 401.

Мутации (Server Actions в `app/actions.ts`) проверяются отдельно от страниц, независимым слоем — `requireEditorAuth()` (`lib/auth.ts`) первой строкой в каждом editor-only экшене (~43 из 50 экспортов). Пропускает при валидной сессионной куке (её ставит `middleware.ts` по тому же `?secret=`) либо при заголовке `x-editor-token`, совпадающем с `EDITOR_SECRET` (curl/сервер-к-серверу). `SESSION_SECRET` подписывает эту куку (JWT, `jose`) — отдельный секрет, не светится в URL; сгенерировать `openssl rand -base64 32` или аналог, разный для dev и для Vercel Production/Preview.

`CRON_SECRET` защищает роуты `/api/cron/*` (Vercel Cron шлёт `Authorization: Bearer <значение>`) — без него роут открыт.

`SENDPULSE_TG_BOT_ID`/`SENDPULSE_TG_BOT_NAME`/`SENDPULSE_TG_START_FLOW_ID` — Telegram-бот, созданный через @BotFather и подключённый в SendPulse; работодатель подписывается персональной `tg.pulse.is`-ссылкой, дальше получает дублирующий пуш о новом выпуске рядом с email.

`SENDPULSE_WA_BOT_ID`/`SENDPULSE_WA_TEMPLATE_NAME` — WhatsApp-бот в SendPulse и имя одобренного Meta шаблона сообщения; в отличие от Telegram подписка не нужна — шаблон шлётся напрямую на телефон работодателя. Пока `SENDPULSE_WA_TEMPLATE_NAME` не задан (или шаблон не прошёл модерацию Meta), вся ветка молча неактивна. Даже при настроенных переменных реальная рассылка не включится сама — отдельный тумблер в `/editor/settings` (по умолчанию выключен), плюс независимая от тумблера тестовая отправка на произвольный номер.

`GEMINI_API_KEY` — ключ из Google AI Studio (бесплатный тариф, но сам Google Cloud проект должен иметь включённый billing), используется только для поиска дублей кандидатов (секция «Поиск дублей кандидатов» на `/editor/settings`); при отсутствии ключа или ошибке квоты секция просто показывает сообщение об ошибке, остальное приложение не затрагивается.

`APP_URL` используется для формирования ссылок на выпуск/резюме (`/list/[listId]`, proxy-ссылки на резюме) — эти ссылки сохраняются и рассылаются, поэтому значение должно совпадать для всех, кто их открывает (даже при локальной разработке против общей базы, см. ниже).

== Запуск локально

[source,bash]
----
npm install
npm run dev
----

Приложение доступно на http://localhost:3000.

CAUTION: Локальный `npm run dev` обычно указывает на ту же базу (Neon), что и продакшн — отдельного стенда нет. Ссылки на резюме и на выпуски, сохранённые в базе, абсолютные (`APP_URL/...`) и всегда ведут на `APP_URL` из `.env.local`, даже если открыты со страницы, отрендеренной локально.

== Где что хранится

Все «боевые» данные — в Neon; Google Sheets не участвует в обычной работе приложения вовсе:

[cols="2,1,3", options="header"]
|===
| Данные | Хранилище | Почему

| Кандидаты (профили, регистрации)
| Neon
| Полный жизненный цикл через UI редактора. Google-таблица — опциональный ДОПОЛНИТЕЛЬНЫЙ канал массового ввода (кнопка на `/editor/settings` читает новые строки в Neon), не альтернативное хранилище и не редактируется приложением в ответ

| Работодатели, компании, стримы
| Neon
| Полный жизненный цикл (регистрация → подтверждение → редактирование → отключение/архивация → удаление) через UI

| Выпуски и подборки
| Neon
| Заголовок выпуска (`mailingLists`) отделён от содержимого (`selections`) — подборка готовится заранее и независимо, выпуск только выбирает уже готовые

| Запросы на контакт
| Neon
| Приложение — единственный писатель, редактор никогда не правит эти строки напрямую

| История версий резюме кандидата
| Neon
| Отдельная таблица (`candidateResumes`)

| Просмотры выпуска работодателями
| Neon
| `releaseViews` — своя статистика «открыл/не открыл» надёжнее трекинг-пикселя SendPulse, с разбивкой по каналу (email/Telegram/WhatsApp)

| Настройки и тумблеры автоматики
| Neon
| Генеричная key-value таблица `settings` — любая будущая настройка пишется туда же, не отдельной колонкой/таблицей

| Файлы резюме
| Vercel Blob (приватное)
| Доступ только через прокси `/api/resume`
|===

Подробности и статус миграции — `docs/backlog.adoc`, раздел «Приложение: переход на реляционную СУБД».

== Доступ к выпуску `/list/[listId]`

[cols="2,3", options="header"]
|===
| Параметр | Результат

| `?e=[employer_token]`
| Всегда резолвится «как у этого работодателя»: личная подборка без фильтра, если на него заведена, иначе дефолтная с геофильтром/исключениями — независимо от того, передан ли вместе с ним `?secret=`

| `?secret=[EDITOR_SECRET]` (без `?e=`)
| Дефолтная подборка без фильтра — просмотр редактора; если дефолтной нет вовсе — состояние «подборка не готова» (HTTP 200, не 404)

| *(без параметров)*
| 404
|===

== MCP-сервер (ИИ-ассистент)

`/api/mcp` — удалённый MCP-коннектор для Claude Desktop/claude.ai: поиск/просмотр/правка кандидатов, подтверждение/отклонение/пауза, резюме для суммаризации, плюс готовые сценарии (prompts) «саммари кандидата» и «скрининг по критериям отсева» со своими гайдами в `lib/mcp/guides/`. Авторизация — собственный OAuth 2.1 (Authorization Code + PKCE, Dynamic Client Registration), логин тем же `EDITOR_SECRET`, но через короткоживущие отзываемые токены, не статичный bearer в конфиге клиента. Подробности и устройство — `CLAUDE.md`, раздел «MCP-сервер»; как подключиться и пользоваться — `docs/manager-playbook.adoc`, раздел «Подключение ИИ-ассистента (Claude Desktop)».

== Добавление новой функциональности

=== Новое поле у кандидата/работодателя

Кандидаты и работодатели полностью живут в Neon — поле добавляется через схему (см. ниже), не через Google Sheets. `lib/sheets.ts`/`lib/sheets-import.ts` (`HEADER_ALIASES`, `mapHeader()`) касаются только опционального канала массового импорта кандидатов — трогайте их, только если поле должно быть доступно и через импорт из таблицы.

=== Новая таблица или поле в Neon

. Добавьте/измените схему в `lib/db/schema.ts` (Drizzle). Для пере-ограниченной по размеру event-лог-таблицы (как `releaseViews`) — добавляйте индексы сразу, не по умолчанию: большинство таблиц в этой схеме обходятся без индексов именно потому, что их размер естественно ограничен (одна строка на кандидата/работодателя/версию резюме), это не универсальное правило.
. `npm run db:generate` — сгенерировать миграцию (`drizzle-kit`), затем `npm run db:migrate` — применить.
. CRUD-функции — в соответствующем файле `lib/db/*.ts` (`import "server-only"`, плоские async-функции, без классов).

=== Новый Server Action

Добавьте async-функцию с директивой `"use server"` в `app/actions.ts`. Если экшен editor-only и мутирует данные — первой строкой вызовите `requireEditorAuth()` (`lib/auth.ts`); постраничная защита `?secret=` эту проверку не заменяет, у мутаций отдельный, независимый слой.

Для мутаций, которые должны обновить UI редактора, вызывайте `revalidatePath(...)`.
Для ожидаемых пользовательских ошибок (валидация, дубликаты) — возвращайте `{ ok: false, error }` вместо `throw`: Next.js в production-сборке заменяет сообщение любого `throw new Error(...)` из Server Action на общий текст, чтобы не утекали детали непредвиденных ошибок — это ломает вывод ожидаемых сообщений пользователю (пример — `registerEmployer()`).

=== Новый раздел редактора

. Создайте `app/editor/<раздел>/page.tsx` с проверкой `?secret=` (страница) — она не заменяет `requireEditorAuth()` для любых мутаций, вызываемых с этой страницы.
. Добавьте пункт в массив разделов в `components/editor-nav.tsx`.

=== Новая SendPulse-переменная контакта (email)

Добавьте ключ в объект `variables` внутри `syncEmployerToSendPulse` (`app/actions.ts`).
В шаблоне письма используйте `{{имя_переменной}}`.

Переменные чат-бота (Telegram/WhatsApp) — отдельный механизм, не этот: см. `lib/sendpulse.ts`.
