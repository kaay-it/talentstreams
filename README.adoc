= TalentStreams
:toc: left
:toc-title: Содержание
:toclevels: 2

Платформа персонализированных подборок проверенных кандидатов для работодателей Центральной Азии.

Работодатели получают email-рассылку с анонимными карточками кандидатов.
Ссылка в письме персонализирована — каждый работодатель видит только тех кандидатов, кто не исключил его компанию или отрасль из своих предпочтений.

== Технический стек

* *Next.js 14* (App Router, Server Components, Server Actions)
* *TypeScript*
* *Google Sheets* — профили кандидатов, подборки рассылок (Service Account API v4)
* *Neon (PostgreSQL)* — работодатели, запросы на контакт, стримы, история версий резюме (Drizzle ORM + neon-http driver)
* *Vercel Blob* — приватное хранилище файлов резюме
* *SendPulse* — email-рассылки (адресные книги, кампании, merge-теги)
* *Tailwind CSS + lucide-react*

== Переменные окружения

Создайте файл `.env.local` в корне проекта:

[source,env]
----
# Google Sheets
GOOGLE_SHEET_ID=...
GOOGLE_SERVICE_ACCOUNT_JSON={"type":"service_account","project_id":"...","private_key":"...","client_email":"..."}

# Neon (PostgreSQL)
DATABASE_URL=...

# Vercel Blob
BLOB_READ_WRITE_TOKEN=...

# SendPulse
SENDPULSE_CLIENT_ID=...
SENDPULSE_CLIENT_SECRET=...
SENDPULSE_MASTER_BOOK_NAME=Default
SENDPULSE_FROM_EMAIL=hello@example.com
SENDPULSE_FROM_NAME=TalentStreams

# Приложение
APP_URL=https://your-domain.com
EDITOR_SECRET=your-secret-string
----

`EDITOR_SECRET` защищает `/editor` и `/api/publish` — без него страница возвращает 404, а API-роут отвечает 401.

`APP_URL` используется для формирования proxy-ссылок на резюме (`APP_URL/api/resume?url=...`) — эти ссылки сохраняются в базе, поэтому значение должно совпадать для всех, кто их открывает (даже при локальной разработке против общей базы, см. ниже).

== Запуск локально

[source,bash]
----
npm install
npm run dev
----

Приложение доступно на http://localhost:3000.

CAUTION: Локальный `npm run dev` обычно указывает на ту же базу (Neon) и ту же таблицу Google Sheets, что и продакшн — отдельного стенда нет. Ссылки на резюме, сохранённые в базе, абсолютные (`APP_URL/api/resume?...`) и всегда ведут на `APP_URL` из `.env.local`, даже если открыты со страницы, отрендеренной локально.

== Где что хранится

Данные разделены между Google Sheets и Neon — не по историческим причинам, а по тому, кто их пишет:

[cols="2,1,3", options="header"]
|===
| Данные | Хранилище | Почему

| Кандидаты (профили, регистрации)
| Google Sheets
| Часть полей всё ещё правится только напрямую в таблице (`bio`, `industry`, `func` и т. д.) — полный редактор в UI пока не построен

| Стримы
| Neon
| Полный CRUD через `/editor/streams`, таблицу больше не открывают

| Работодатели
| Neon
| Полный жизненный цикл (регистрация → подтверждение → редактирование → отключение → удаление) через UI

| Запросы на контакт
| Neon
| Приложение единственный писатель — редактор никогда не правит эти строки напрямую

| История версий резюме кандидата
| Neon
| Отдельная таблица (`candidateResumes`) — Sheets хранит только URL последней версии

| Файлы резюме
| Vercel Blob (приватное)
| Доступ только через прокси `/api/resume`
|===

Подробности и статус миграции оставшихся таблиц — `docs/backlog.adoc`, раздел «Приложение: переход на реляционную СУБД».

== Доступ к подборке `/list/[listId]`

|===
| Параметр | Результат

| `?e=[employer_token]`
| Персонализированная подборка: кандидаты фильтруются по предпочтениям работодателя (исключённые компании/отрасли, гео)

| `?secret=[EDITOR_SECRET]`
| Все кандидаты без фильтрации (просмотр редактора)

| *(без параметров)*
| 404
|===

== Добавление новой функциональности

=== Новое поле в профиле кандидата (Google Sheets)

. Добавьте ключ в массив `KNOWN_KEYS` (`lib/sheets.ts`).
. Добавьте поле в тип `Profile` или `Candidate` (`lib/sheets.ts`).
. Добавьте алиасы в `HEADER_ALIASES` (английское и русское название заголовка) — используются функцией `mapHeader()` везде при чтении/записи.
. Заполните поле в `buildProfile()` / `rowToRecord()`.

=== Новая таблица или поле в Neon

. Добавьте/измените схему в `lib/db/schema.ts` (Drizzle).
. `npm run db:generate` — сгенерировать миграцию (`drizzle-kit`), затем `npm run db:migrate` — применить.
. CRUD-функции — в соответствующем файле `lib/db/*.ts` (`import "server-only"`, плоские async-функции, без классов).

=== Новый Server Action

Добавьте async-функцию с директивой `"use server"` в `app/actions.ts`.
Для мутаций, которые должны обновить UI редактора, вызывайте `revalidatePath(...)`.
Для ожидаемых пользовательских ошибок (валидация, дубликаты) — возвращайте `{ ok: false, error }` вместо `throw`: Next.js в production-сборке заменяет сообщение любого `throw new Error(...)` из Server Action на общий текст, чтобы не утекали детали непредвиденных ошибок — это ломает вывод ожидаемых сообщений пользователю (пример — `registerEmployer()`).

=== Новый раздел редактора

. Создайте `app/editor/<раздел>/page.tsx` с проверкой `EDITOR_SECRET`.
. Добавьте пункт в массив разделов в `components/editor-nav.tsx`.

=== Новая SendPulse-переменная контакта

Добавьте ключ в объект `variables` внутри `syncEmployerToSendPulse` (`app/actions.ts`).
В шаблоне письма используйте `{{имя_переменной}}`.
